# 部分付款與 AR/AP 拆分、篩選

本輪依使用者指示補上付款備忘錄部分付款 UI，再完成 AR/AP 拆分與篩選。
沿用既有核准政策：付款先建立草稿，過帳成功才計入付款；AR/AP 逐筆明確
選擇已過帳分錄行追蹤，不強制所有交易分類。正式簽章維持暫緩。

## 會計與資料界線

- 金額使用整數字串及 BigInt；後端使用精確 i64 與檢查式加總。
- 付款備忘錄的草稿建立採資料庫交易，同時檢查計畫版本、有效狀態、剩餘額
  及現有草稿。付款仍須另外過帳；已沖銷付款不再扣減剩餘額。
- AR/AP 拆分總額須等於完整來源行，單批最多 100 筆，後端原子驗證及登記。
  不是把來源行的一部分留待後續任意補登。
- 分配同時受款項未結額及付款行可分配額限制，還須符合科目、方向、日期
  及未沖銷條件。解除分配保留原分配及原因；有有效分配的分錄不能先沖銷。
- 篩選呈現的是明確登記款項，不代表所有應收應付或完整科目餘額。
