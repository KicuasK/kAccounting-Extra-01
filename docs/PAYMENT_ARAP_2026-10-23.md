## 操作界線

- 付款備忘錄的到期日、必要性與預留總額是規劃資料，不是負債或費用分錄。
  必須明確選擇借方科目、付款資產及日期建立草稿，核對後另行過帳。
  草稿建立或儲存不代表已付款；過帳與付款連結須同交易成功。
- AR/AP 的款項及收付分配是已過帳分錄的追蹤明細，不直接修改科目餘額。
  每筆款項來自明確選擇的已過帳行；以永久 ID 連結，不靠名稱推斷。
  未分類／未分配金額必須可見，不把局部明細冒稱整個科目的完整對帳。
- 解除收付分配保留原因、原分配及稽核歷史，不刪除原付款分錄。
  沖銷涉及仍有效的分配時，須先解除；更正仍使用既有會計更正流程。
- 寫入沿用同源與選簿世代檢查。未知寫入結果保留輸入並要求核對，不自動重送。

### Safari 實際操作

僅使用一次性假帳簿與記憶體金鑰：

- 新增 123 元必要付款計畫，列表顯示已付 0、剩餘及必要總額 123。
- 明確選驗收費損與現金科目建立草稿，導向分錄編輯，借貸各 123；沒有自動過帳。
  另行確認過帳後，備忘錄顯示已付 123、剩餘與必要總額 0。
- 明確選已過帳假資料行，登記 AR 原額 9,007,199,254,740,993，畫面顯示完整精度。
  選同科目反向行分配 123 後，未結為 9,007,199,254,740,870。
  填原因解除後，未結恢復原額，分配歷史仍顯示 123 及解除原因。
- 僅關閉本輪測試視窗，測試服務已停止，3000 埠無 listener。

AP、部分付款及沖銷阻擋有自動化測試；本輪不冒稱所有變體均做過 Safari 實機操作。

### 目前範圍與限制

- 備忘錄 UI 建立剩餘全額草稿；API 支援部分付款。已有有效付款或未刪草稿時，
  計畫不能直接編輯或取消；須先按既有流程處理草稿／沖銷付款，保留歷史。
- AR/AP UI 先提供整行登記一筆款項與逐筆分配；API 支援整行拆多筆。
  此為明確選行追蹤，不是指定科目全面強制分類。款項登記後不提供原地編輯／刪除。
- 本輪沒有加入現金資產預留覆蓋率、帳齡報表、背景通知、重複付款排程，
  也沒有擅自實作信用卡政策或 TPASS。
