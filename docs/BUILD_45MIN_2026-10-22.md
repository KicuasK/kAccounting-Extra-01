## Implemented behavior

- Encrypted database, manifest and complete snapshot attachment set are bound
  to the recipient envelope and independently verified before/after publication.
- Import creates a new private book and fresh local device key. Only ciphertext
  descriptors change on an unpublished copy inside a transaction, with the exact
  immutable trigger restored before final audit. Journal and audit data remain.
- Export restart recovery authenticates source-wrapped recovery context. Import
  recovery authenticates initial/READY contexts and complete published content;
  active, modified or uncertain work remains preserved. Recovery never publishes
  an old stage, selects a book or deletes a key/source package.
- HTTP attachment processing uses bounded 64 KiB crypto bridges, not full-file
  plaintext buffers or plaintext attachment intermediates. Downloads authenticate
  fully before starting and use forced-download headers.
- Historical schemas are validated against exact migration prefixes. Live
  migration starts only after a durable independently verified encrypted backup.
  The checkpoint can restore to a new current-schema book even if the old live
  database is damaged or interrupted migration work remains.
- Discovery is key-free and SQLite-free. A selection replacement verifies the
  new book before releasing the old one. This is a model/CLI, not HTTP hot switch.
